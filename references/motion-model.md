# 运动建模参考

只在需要推导场景结构、接触、几何或循环时读取。所有结论最终都要落到实际 SVG 属性和浏览器画面。

## 1. 场景契约表

写代码前，为场景建立可核对的表。不要只列“画什么”，要列“什么必须成立”。

```text
实体/部件：jelly-bell（弹性伞）、tentacle[0..7]（柔性）、lantern（刚性，包含于伞内）
关系：tentacle[i].root 附着于 bell.rim-root[i]，全周期；
      lantern.orb 包含于 bell.interior，全周期；
      主体包围盒在工作区内，所有姿态。
驱动：bell.pulse(t) → rim.scale；tentacle[i].phase = pulse.phase + i·lag；
      lantern.swing(t) 独立 2 周期/主周期。
关键事件：无落地事件；灯球摆幅极值 → 与伞壁最近点检查。
主周期：12 s；伞 4 s、触手 6 s、灯摆 6 s、上浮 12 s。
强制约束：8 个触手根部不脱开；灯球始终在伞内；3 画幅不裁切；边界连续。
质量目标：深海层次、半透明材质、粒子节奏。
```

对每个关系写清：

- **类型**：连接/接触/支撑/附着/包含/遮挡。
- **参数化生效区间**：`[t0,t1)`、`x ∈ [a,b]`、`contact == true`。
- **建立/解除条件**：何时、因为什么建立或解除。
- **失败可观察量**：断开的像素距离、穿透深度、越界框。

禁止用“视觉上差不多”替代有效区间。若关系只在一段动作内成立，必须明确这段区间；不要默认全周期成立。

## 2. 几何唯一来源

建议用一个可序列化对象集中保存运动相关几何：

```js
const SPEC = {
  origin: { x: 600, y: 430 },
  bell: {
    rx: 220, ry: 188, scallop: 16, segments: 8,
    pivot: { x: 0, y: 0 },                 // 与身体的连接点
  },
  tentacles: [
    { rim: 0.875, len: 250, phase: 0.0 },  // rim ∈ [-1,1]，局部根点由伞缘生成
    // ...
  ],
  lantern: {
    anchor: { x: 0, y: -210 },             // 伞的局部坐标
    length: 90, radius: 14,
    maxSwing: 0.085,                        // 已解析检查：摆到边界仍在伞内
  },
  camera: { center: { x: 600, y: 470 }, safe: { l: 300, t: 140, r: 900, b: 800 } },
};
```

规则：

1. 部件先用**局部坐标**定义形状。根点在原点或明确的局部枢轴；场景中只通过父级变换定位。
2. 父子变换使用 `translate/rotate/scale` 的组合，不要在每个子部件里重复计算父级世界位置。
3. 同一连接点只有一个 ID/公式。需要同时画两块刚体时，两者分别在局部坐标中包含该锚点，再施加同一父变换。
4. 静态标记和动画都读同一份数据。若为可读性写静态 SVG，初始 `transform` 也应由构建/初始化代码设置，至少不能让动画另抄一组关键坐标。
5. 验证时从**渲染后的 DOM** 重新取点，不复用生成公式：
   - `getCTM()`/`getScreenCTM()` 获取最终变换；
   - `getPointAtLength()` 采样路径实际点；
   - `getBoundingClientRect()` 检查屏幕边界；
   - `isPointInFill()` / `isPointInStroke()` 检查包含/描边接触；
   - 对实际路径采样求最近距离，而不是重算生成代码。

### 可达性与冲突前置检查

在写动画循环前，把每个角度/位移范围代入几何，检查：

- 关节连接点是否仍然重合；
- 接触对象是否仍相交或保持贴合；
- 包含物是否仍在容器填充内；
- 刚性长度/面积是否不变；
- 子部件是否越过父轮廓、遮挡边界或画布安全区；
- 同一时刻的多个约束是否互相矛盾。

有冲突时，先改设计参数或限制行程；不要 `Math.min/Math.max` 悄悄砍掉目标值。若运动本身就有物理限位，限位应是明确、可见、可解释的约束，而不是掩盖求解失败。

## 3. 共享状态与步态/机械联动

存在机械联系或因果关系的动作，共用一个状态源，再从状态推导位置和速度。

### 车轮与车体

如果无滑动滚动：

```text
车体位移 x(t) = x0 + r * (θ(t) - θ0)
轮转角 θ(t) = θ0 + (x(t) - x0) / r
```

不要分别给车与轮写两个速度，否则加速/暂停会打滑。验证时比较轮缘接触点速度与地面速度，误差应在场景容差内。

### 足部接触

支撑脚的脚掌在一段接触区间内应固定在世界坐标（跑步时可约定地面速度），摆动脚才移动。接触区间之外才允许离地。切换瞬间检查位置连续性和速度设计。若使用正弦腿，必须另算接地轨迹，不能把整条腿当成摆锤并声称没有滑步。

### 附着/包含物

- 附属物使用父级坐标或共享锚点，位置由父级变换推导。
- 发光、粒子、纹理、装饰若在视觉上属于主体，应随主体的平移/旋转/缩放同步，不能各自独立漂移。
- 包含关系在全周期检查；仅当容器透明度足以隐藏时才可简化，但仍需保证渲染结果不穿帮。

### 柔性形变

用连续函数驱动形状，例如：

```js
const wave = Math.sin(TAU * cycles * u + phase + t * TAU * K);
const x = baseX + amplitude * taper(u) * wave;
```

- 根部 `u=0` 位移为 0，保证仍连接；越靠末端幅度越大。
- 同一对象相邻控制点相位连续，避免折角和闪烁。
- 形状生成/更新引用的根部锚点必须来自上游共享定义。
- 刚体不因动画被拉伸；柔体的长度变化写成可解释的形变规律。

## 4. 时间、周期和循环闭合

### 选择一个主周期

所有周期函数都写成主周期的整数倍频率：

```text
θ(t) = θ0 + A · sin(2π · k · t / P + φ)
```

- `k` 是整数；`t=P` 与 `t=0` 的相位相同。
- 不同部件可有不同整数频率与相位，不要求同相。
- 若某个装饰的真实周期是 `q`，用 `LCM(P,q)` 作为全局主周期，或把它改为 P 的整数分频/倍频。
- 只有当状态可证明以 P 为周期时才允许 `% P`。对于有内部状态、事件队列、随机步进的对象，不能因为整个页面共享时间就回绕它。

### 循环边界检查

在边界附近取 `P-ε`、`P`、`P+ε` 的实际渲染快照，与“正常一帧间隔”的 `0`、`δ` 比较：

- 位置/姿态在 `P-ε → P` 的变化不应明显大于普通相邻帧。
- 速度方向应连续；若设计上在边界有撞击/切换，应显式建模事件，而不是碰巧接上。
- 对周期函数可同时检查导数：`v(0−) ≈ v(P−)`。
- 不同数值表示可以等价，但必须验证等价性。典型例子：粒子在屏幕外重置、透明度已为 0、遮罩完全覆盖。等价条件需写成断言。

### 图案/重复纹理

若图案真实重复间距为 `d`（世界单位），周期内平移量必须是 `n·d`（n 为整数）。检查：

```text
shift(T) = n · d,  n ∈ ℤ
```

不要只检查代码里写的 `period` 变量。测量实际路径/图案的重复间距，再用最终变换验证。若图案相位用 `t % d / speed` 计算，确认边界两端的可见图案完全重合，不出现半格跳动。

### 事件与遮挡

接触、脱离、遮挡关系变化需要单独时间点，不能只依赖均匀采样。对每次关系切换，检查切换前、切换瞬间、切换后；遮挡关系还要检查前后层级 `<g>` 的顺序和实际可见像素。

## 5. 时钟、暂停与页面生命周期

推荐结构：

```js
const PERIOD_MS = 12000;
let simMs = 0;            // 当前相位
let lastFrame = null;
let rafId = 0;
let playing = true;
let manualPause = false;

function tick(now) {
  if (!playing) return;
  if (lastFrame !== null) simMs += now - lastFrame;
  lastFrame = now;
  renderAt(simMs);        // renderAt 内部才做周期归一化
  rafId = requestAnimationFrame(tick);
}

function play() {
  if (playing) return;
  playing = true;
  lastFrame = null;       // 关键：恢复时不补帧
  rafId = requestAnimationFrame(tick);
  syncControl();
}

function pause() {
  playing = false;
  cancelAnimationFrame(rafId);
  lastFrame = null;
  syncControl();
}

document.addEventListener('visibilitychange', () => {
  if (document.hidden) {
    cancelAnimationFrame(rafId);
    lastFrame = null;
  } else if (playing && !manualPause) {
    lastFrame = null;     // 重新起算，避免后台时间追赶
    rafId = requestAnimationFrame(tick);
  }
});
```

要求：

- **一个时钟控制全部场景运动**。暂停按钮冻结该时钟；恢复从冻结相位继续。不要只暂停部分动画，也不要只暂停 CSS 而漏掉 JS。本项目架构默认要求场景运动全部走 JavaScript 时钟；SMIL 或场景 CSS 动画会绕过统一冻结与相位审计，不应使用。
- 页面隐藏时取消帧循环；恢复时重置 `lastFrame`。不要累加 `now - hiddenStart`。
- 页面切换可能伴随多帧间隔，不要把异常大的 `dt` 通过静默限幅藏起来；应当只在生命周期恢复时明确重置时间基准。普通渲染卡顿可按设计保留真实时间，但需确保不会出现时间跳跃导致的接触/穿透。
- `prefers-reduced-motion` 独立于暂停：初始停在代表帧，显示可播放控件；用户显式点击后可启动。偏好变化、按钮动作文案、`data-playing`、状态说明同步更新。
- 所有场景动画应采用同一状态函数，使暂停/恢复和循环验证可复现。

## 6. 布局与取景

优先使用统一场景坐标和动态取景，而不是把场景硬缩到某个 `viewBox`：

1. 定义主体在场景坐标中的安全包围盒，包含运动包络、描边、滤镜、光晕。
2. 读取舞台实际像素尺寸，按目标宽高比计算相机 `viewBox`：先保证 `safe` 包围盒 + 内边距完整，再扩展画面到舞台比例。
3. 用 `preserveAspectRatio="xMidYMid meet"`，让 SVG 坐标系与舞台比例一致，避免主体被裁切。
4. 背景层覆盖所有可能相机范围，装饰可随画幅重排或独立绘制。
5. 控制条/标题叠加时，验证主体最终屏幕包围盒不与按钮相交；必要时把 UI 留白纳入安全区。
6. 只在某个对象上缩放时，重新计算它的连接点、环境接触和运动速度，不能沿用缩放前的约束结论。

三种目标画幅必须用真实浏览器检查：390×844、844×390、1440×900。横屏最紧的是高度，竖屏最紧的是宽度；不要只验证桌面。

## 7. 常见失败模式

- 视觉上“差不多接上”，验证时取的是两套坐标。
- 用 CSS 动画做部分元素、JS 时钟做另一部分，暂停后不同步。
- 每个动画自动 `% P`，但没有证明状态确实以 P 为周期。
- 粒子在边界直接回到底部，透明度却未归零，产生闪跳。
- 主体整体缩放后，细小装饰没有同步，连接点漂移。
- 循环周期是 12 s，但触手用了 5 s 的周期，主循环并不闭合。
- 在 390×844 下靠 `overflow:hidden` 裁掉一部分主体，桌面却看起来正常。
- 后台恢复时 `now - last` 累加了 10 分钟，页面瞬移。
- 减少动态只改了 CSS，JS 时钟仍在跑，重新打开时相位跳变。
- 验证只检查了代码常量或首帧截图，没有最终渲染证据。
